How a real agent is built

1 · Trigger

Start manually with a button or controlled test input.

2 · Observe

Read only the least amount of information needed.

3 · Decide

Ask the model to select a safe next action or produce a structured response.

4 · Validate

Check facts, numbers, permissions and malformed outputs.

5 · Approve

A person approves messages, purchases, deletion or other external changes.

6 · Act and log

Perform approved operations, record results, retry safely and stop on errors.

A tiny agent loop in Python

This is a safe deterministic illustration of observe → decide → act. It is not a live LLM agent.

tasks = [
    {"name": "Pay electricity bill", "urgent": True},
    {"name": "Read a chapter", "urgent": False},
    {"name": "Prepare meeting notes", "urgent": True},
]

def observe(items):
    return [x for x in items if x.get("name")]

def decide(items):
    return sorted(items, key=lambda x: not x.get("urgent", False))

def act(items):
    return [f"{i+1}. {item['name']}" for i, item in enumerate(items)]

print("\n".join(act(decide(observe(tasks)))))

To make it a model-backed agent, learn the OpenAI Agents SDK or n8n AI tutorial. Run tools with narrow permissions and protect API keys server-side.

Vibe coding to GitHub Pages: step by step

  1. Describe your site's purpose, users, accessible navigation and expected behavior in plain English.
  2. Ask AI to create three files: index.html, styles.css and app.js. Explain what each does.
  3. Review generated code for errors, missing labels, unsafe HTML injection and accidental passwords.
  4. Preview locally; try keyboard navigation, 360px mobile width and two browsers.
  5. Create a public GitHub repository with a README; upload the static files at its root.
  6. Open repository Settings → Pages → Build and deployment → Deploy from a branch → main and /(root).
  7. After GitHub shows a successful deployment, visit https://USERNAME.github.io/REPOSITORY/.
  8. Open the public URL in a private browser tab; retest links, layout, quiz, saving and accessibility.
  9. For changes, commit to main and retest after deployment. Use Git history for rollback.
Never do this: Put an API key in JavaScript running on GitHub Pages. Static files are public. To call private APIs, use a secure server-side integration.

Quality checklist

  • All links work and no page displays an error.
  • Readable at desktop and small mobile widths; keyboard works.
  • Privacy and permissions are explained to users.
  • Model answers have source verification where factual accuracy matters.
  • All agent actions involving external changes ask for approval.
  • Test malicious prompts, missing inputs and incorrect calculations.
  • OWASP reviews and dependency checks are documented; no claim of zero vulnerabilities.
